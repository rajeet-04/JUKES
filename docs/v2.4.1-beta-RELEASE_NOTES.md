# v2.4.1-beta - RELEASE NOTES

Release Date: 2026-10-07

## Overview

v2.4.1-beta is the Liquid Glass release: a Home discovery feed, a redesigned Library and Search, a new update sheet, softer haptics, and recommendations that start from YouTube Music directly.

## 🚀 Features & Enhancements

### Home

- Home is now a discovery feed: new releases from artists you play, "Because you played…" and "More like…" lists built from your history, and a "Back in rotation" row. Resume playback stays in the mini player.
- Each section loads on its own behind a skeleton, so the first rows appear in about two seconds instead of waiting for everything. An offline notice with Retry shows when there is no connection, and the feed fills in by itself when it returns.

### Library, Search and Albums

- Library and Search rows are flat and hairline-divided; glass appears on swipe reveals and floating controls (search field, filter chips, tab pill).
- Library actions use glass sheets with batch Undo; albums can be saved for offline playback.
- New JukeIcons icon set across the app.

### Updates

- New update sheet: version change, size and date, readable release notes, live download progress, and install.
- The GitHub check has a timeout, runs at most every 6 hours when up to date, hides pre-releases from stable builds, remembers "Not now" for a day, and treats a release as critical only when its tag says `hotfix` or `emergency`.

### Haptics

- A very mild tap for buttons, a barely-there tap when switching tabs, one clean tap for completed actions (add to queue, favourite), and one slight long buzz for delete. Lyrics-sync no longer buzzes while dragging.

### Player and Lyrics

- Shared artwork transition and gesture dismissal for the full player; faster artwork pager.
- Lyrics: romanized lyrics use one request per script with a fallback and back-off on rate limits; LRCLib entries without a duration now work.
- Glass tab bar that folds into the mini player row while scrolling.

## 🔧 Fixes & Under the Hood

- Recommendations try YouTube Music directly first and use the shared JUKES backend only as a fallback, so one heavy listener no longer skews other users' suggestions. Home follows the same order.
- Playback starts on the first audio bytes, with the backend's `/v1` API warming upcoming songs.
- Dead code removed and IDE warnings cleared; build tooling upgraded (Gradle, AGP, Kotlin, dependencies).

## 📦 Build

- Version: `2.4.1-beta` (versionCode 19).
- Release build is R8-minified with resource shrinking; `Log.d/v/i/w` calls are stripped.
