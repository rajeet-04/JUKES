# v2.8.0-beta - RELEASE NOTES

Release Date: 2026-11-08

## Overview

v2.8.0-beta makes songs start faster, shows Up Next songs in the queue as soon as each one is ready, and fixes a crash when resuming from the notification.

## 🚀 What's new

- **Faster song start.** A song you have not played before usually starts in about 1.5 to 3 seconds. The app asks the server to wait for the file, so one request replaces the old prepare-then-poll steps, and it opens the connection to the server as soon as Search opens.
- **Up Next fills in as it loads.** Songs are added to the queue one by one as each finishes fetching, instead of all at once at the end.
- **Go to album / artist** from the song menu in Search and Library (one shared song action sheet).
- **Crash reports.** Crashes are reported to the developer (with tokens and emails removed) so they can be fixed.

## 🔧 Changes

- Background queue fills pause while a song you picked is loading, so it gets the full connection.
- The next song is warmed up fully; songs further down the queue are only looked up, which keeps server load down.
- The app sends the exact video it already matched, so the server skips its own title search.
- A failed song is no longer retried over and over when the video cannot be fetched (for example age-restricted); it moves on to the next source sooner.
- Retryable failures wait 1 s, then 2 s, and give up after two retries.
- A stream that answers "not found" or "too many requests" is retried once instead of stopping playback.
- Matches the server marks as the right song but with a different credited artist, or a longer music-video upload, now play.

## 🐛 Fixes

- No more crash when you resume playback from the notification after a long pause and the system refuses to start the service in the foreground.
