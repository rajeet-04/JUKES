## Executive Summary

JUKE v2.0.0-stable marks the official graduation from beta to production software. This is a **feature-complete, battle-tested music streaming application** that combines Spotify integration, AI-powered recommendations, offline playback, and professional audio controls into a polished, enterprise-grade experience.

- ✅ **Zero Breaking Changes**: Seamless upgrade from any v1.0.x version

- ✅ **4 API Integrations**: Spotify, YouTube Music, Spotdown, LRCLib
- ✅ **Professional Audio**: Volume booster, sleep timer
- ✅ **Open Source**: Code freely auditable and community-driven

## 🏗️ Architecture Deep Dive

### Design Patterns

**MVVM (Model-View-ViewModel)**
```
View (Composable) ←→ ViewModel (StateFlow) ←→ Repository (Services/Room)
```

**Repository Pattern**
```
Services → Data Access Objects → Room Database
Services → API Clients → External APIs
```

**Service Locator**
```
MusicService → Download Management
PlaybackManager → ExoPlayer Control
QueueManager → Smart Queue Logic
```

### Layer Separation

**UI Layer** (Jetpack Compose)
- `ui/screens/` - Full-screen composables
- `ui/components/` - Reusable components
- `ui/theme/` - Material Design 3 theming

**ViewModel Layer** (State Management)
- `viewmodels/MusicViewModel.kt` - Central playback state
- `viewmodels/SearchViewModel.kt` - Search and import logic
- `viewmodels/LibraryViewModel.kt` - Library filtering and sorting
- `viewmodels/HomeViewModel.kt` - Home screen widgets
- `viewmodels/*DetailViewModel.kt` - Detail screen logic

**Service Layer** (Business Logic)
- `services/PlaybackManager.kt` - ExoPlayer wrapper
- `services/QueueManager.kt` - Smart queue management
- `services/MusicService.kt` - Download and indexing

**Data Layer** (Persistence)
- `database/MusicDatabase.kt` - Room configuration
- `database/*Entity.kt` - Data model entities
- `database/*Dao.kt` - Database access objects

**Network Layer** (API Integration)
- `network/SpotifyApi.kt` - Official Spotify Web API
- `network/RecommenderApi.kt` - YouTube Music recommendations
- `network/ApiClient.kt` - Shared HTTP client setup

**Models** (Data Classes)
- `models/Track.kt` - Core track model
- `models/SpotifyModels.kt` - Spotify API responses
- `models/SpotdownSong.kt` - Download queue models

### Data Flow

```
User Action
    ↓
Composable State Update
    ↓
ViewModel.event()
    ↓
Coroutine in viewModelScope
    ↓
Service Layer (PlaybackManager/QueueManager)
    ↓
API Client OR Room DAO
    ↓
StateFlow Emission
    ↓
Composable Recomposition
    ↓
UI Update
```

### Database Schema

**Key Entities:**
- `TrackEntity` - Downloaded tracks with metadata
- `PlaylistEntity` - User-created playlists
- `PlaylistTrackCrossRef` - Playlist-to-track relationships
- `FavoriteEntity` - Starred tracks
- `HistoryEntity` - Recently played tracks

**Key DAOs:**
- `TrackDao` - Full CRUD and complex queries
- `PlaylistDao` - Playlist management
- `FavoriteDao` - Favorite tracking
- `HistoryDao` - History management

**Reactive Patterns:**
- All queries return `Flow<T>` for reactive updates
- `collectAsState()` in Compose for UI binding
- Database changes automatically update UI

### Coroutine Scopes

**viewModelScope**: ViewModel lifecycle
- Automatically cancelled on ViewModel.onCleared()
- Safe for all ViewModel operations
- Used for UI-triggered async work

**lifecycleScope**: Activity/Fragment lifecycle
- Automatically cancelled on lifecycle destruction
- Used for one-time operations

**Custom Scopes**: Service classes
- Manual lifecycle management
- Job stored for later cancellation
- Explicit cleanup in destructors

## 🔒 Security & Privacy

### Data Protection

**Local Storage**
- All music stored on-device internal storage
- No cloud upload by default
- Files persist across app updates
- Encrypted per Android security model

**API Credentials**
- Spotify Client ID/Secret in local.properties (not committed)
- Environment variable support for CI/CD
- No credentials in release builds (built-time only)
- API keys never logged

**User Privacy**
- No personal data collected
- Playlist imports only store locally
- Listening history private to device
- Optional PostHog analytics (opt-in)

### Permissions

**Required:**
- `READ_EXTERNAL_STORAGE` - Access device music
- `WRITE_EXTERNAL_STORAGE` - Save downloads
- `INTERNET` - API calls and streaming
- `FOREGROUND_SERVICE` - Background playback

**Optional:**
- `READ_PHONE_STATE` - Call pause/resume
- `RECORD_AUDIO` - Future equalizer visualization

**Handling:**
- Runtime permission requests on Android 6+
- Graceful degradation if permissions denied
- Clear permission rationale in UI
