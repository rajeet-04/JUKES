# JUKE v2.1.1-beta Release Notes

## 🚀 Release Overview

**Release Date:** March 3, 2026  
**Version:** 2.1.1-beta  
**Status:** Beta Release  
**Milestone:** Playback Bug Fixes  
**Type:** Patch Release  

JUKE v2.1.1-beta is a targeted patch release fixing two playback reliability bugs introduced in v2.1.0-beta: duplicate song insertions when swiping queue items, and the player freezing/pausing when a 403 HTTP error is encountered during playback.

---

## 🐛 Bug Fixes

### 1. Swipe-to-Add-Next Firing Multiple Times Per Gesture

**Symptom:** Swiping a track to "Add to Queue Next" would insert the same song repeatedly (up to 16+ times) during a single swipe gesture.

**Root Cause:** `SwipeToDismissBox`'s `confirmValueChange` callback fires continuously every time the dragged item crosses the positional threshold — not just once on release. Since `onAddNext()` was called unconditionally inside the callback, a slow or wobbly swipe could trigger it dozens of times before the finger lifted.

**Fix:** Added an `actionFired` boolean guard using `remember { mutableStateOf(false) }`. The action only fires when `actionFired` is `false`; it is immediately set to `true` to block subsequent calls within the same gesture. It resets to `false` when the state returns to `Settled` (i.e., the item snaps back), allowing the next swipe to work normally.

**File:** `SwipeToAddNextContainer.kt`

---

### 2. Player Pausing / Freezing on 403 HTTP Error (Non-Stream Tracks)

**Symptom:** When a track's audio URL returned a `403 Forbidden` response, the player would simply stop and stay paused. This affected tracks that were queued but not actually saved locally (e.g., recommendations added to a non-stream queue that never completed download).

**Root Cause:** The existing 403 error handler in `PlaybackService.kt` had this gate:

```kotlin
if (track == null || !track.isStream || track.spotifyId == null) {
    Log.w(TAG, "Cannot refresh: track not found, not a stream, or missing spotifyId")
    return@launch  // ← silently exits, player stays paused
}
```

Non-stream tracks (`isStream = false`) hit this early return unconditionally — no skip, no retry, just silence.

**Fix:** The 403 handler is now split into two branches:

**Non-stream tracks** (library/downloaded track with missing or expired file):

- **Online + has `spotifyId`** → Re-downloads via `smartDownloadAndIndex()`, swaps the queue item, resumes playback.
- **Online + no `spotifyId`** → Skips to next track.
- **Offline** → Skips to next track (using `ConnectivityManager` to check network state).
- **Re-download fails** → Skips to next track.

**Stream tracks** (unchanged existing behavior):

- Fetches a fresh stream URL from Spotmate, swaps the expired URL in the queue, resumes. Background-promotes to a local download if the track belongs to a playlist.

**All error paths** now guarantee either playback resumes or the next track is played — the player never stays silently paused.

**File:** `PlaybackService.kt`
