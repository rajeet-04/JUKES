# JUKE v1.0.7-beta Release Notes

## 🎉 Release Overview

**Release Date:** February 15, 2026  
**Version:** 1.0.7-beta  
**Status:** Beta Release  

JUKE v1.0.7-beta delivers powerful new features and critical stability fixes. This release introduces the **Purge** storage cleanup tool, a one-tap **Radio** mode for infinite discovery, **Repeat** controls, **Notification Favorites**, and resolves major playback issues with shuffle mode and Spotdown API connectivity.

---

## 🔑 Key Highlights

### 🗑️ Purge Redundant Tracks

- Navigate to **Settings > Audio Control > Purge Redundant Tracks** to identify and delete unused songs.
- Songs flagged for purging include:
  - **Old & Unplayed**: < 5 plays and not listened to in 14+ days.
  - **Never Played**: 0 plays and downloaded 30+ days ago.
  - **Short Audio**: Duration under 60 seconds (garbage files).
  - **Incomplete Metadata**: Missing thumbnail or unknown artist.
- **Safety**: Favorited tracks and tracks in playlists are always excluded.
- Multi-select deletion with estimated storage savings displayed.

### 📻 Radio Mode

- New **Radio** button on the Player Screen (between Queue and Share).
- Tap to reset the queue to the current song and start receiving fresh recommendations — like starting a personal radio station based on what you're listening to.
- Queue automatically refills with discovered tracks.

### 🔁 Repeat Mode

- Cycle through **Repeat Off → Repeat All → Repeat One** with the new Repeat button in player controls.
- Repeat One loops the current track indefinitely.
- Repeat All restarts the queue from the beginning when it reaches the end.

### ❤️ Notification Favorites

- A **Heart** button now appears in the media notification.
- Tap to toggle favorite status instantly — the icon updates in real-time (filled vs. border heart).
- State syncs with the app UI immediately.

## 🐛 Critical Fixes

### 🔀 Shuffle Queue Premature End

**Problem:** Shuffle mode stopped playing after ~14 tracks instead of the full queue.

**Root Cause:** `player.replaceMediaItem()` inside `onMediaItemTransition` was resetting ExoPlayer's internal shuffle order seed/history on every track transition.

**Fix:** Removed the offending `replaceMediaItem` call. Metadata is correctly set when tracks are initially added via `PlaybackManager`, so this call was redundant and destructive.

---

### 🔀 Shuffle Recommendation Trigger

**Problem:** During shuffle playback, recommendations were triggered prematurely because the app checked the linear queue index instead of the actual shuffle order.

**Fix:** Added `getRemainingTracksCount()` in `PlaybackManager` which traverses ExoPlayer's timeline using `getNextWindowIndex` to accurately count remaining songs in the current shuffle order.

---

### 🔑 Spotdown API Key & Error Handling

**Problem:** Spotdown API started requiring an `x-api-key` header, causing downloads to fail with `Unexpected JSON token` errors.

**Fix:**

- Added `x-api-key` header to `checkDirectDownload` and `downloadSong` requests in `SpotifyApi.kt`.
- Added `SpotdownCheckResponse` data class in `Track.kt` for structured API response handling.
- Implemented robust JSON parsing and network exception handling so failures gracefully fall through to the Spotmate backup API.
